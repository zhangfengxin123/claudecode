Engram: 条件记忆架构的性能优势与机制洞察

执行摘要

本报告对 DeepSeek-AI 和北京大学联合发表的 Engram 论文进行了全面分析。Engram 引入了条件记忆（Conditional Memory）作为稀疏性的新维度，通过现代化的 N-gram 嵌入实现 O1 查找。在严格的等参数、等 FLOPs 对比下，Engram-27B 在多个关键基准测试中显著优于 MoE-27B 基线：

  • 知识检索: MMLU +3.4, CMMLU +4.0
  • 推理能力: BBH +5.0, ARC-Challenge +3.7
  • 代码与数学: HumanEval +3.0, MATH +2.4
  • 长上下文: Multi-Query NIAH 从 84.2% 提升至 97.0%

最令人惊讶的是，尽管设计初衷是辅助知识检索，Engram 在推理和代码/数学任务上取得了更大的收益。机制分析揭示：Engram 释放了主干网络的早期层，使网络对复杂推理"有效加深"，并将注意力容量从局部依赖解放到全局上下文中，从而显著提升长上下文检索能力。

1. 研究背景与核心创新

分析问题
  • 为什么现有的 MoE 架构需要新的稀疏性维度？
  • Engram 的核心设计原理是什么？

1.1 稀疏性的双重维度

现代大型语言模型（LLMs）主要通过 混合专家（Mixture-of-Experts, MoE）实现稀疏性，通过条件计算扩展容量。然而，语言建模本质上包含两个定性不同的子任务：

1. 组合推理（Compositional Reasoning）: 需要深层、动态的计算

2. 知识检索（Knowledge Retrieval）: 大部分文本（如命名实体、公式化模式）是局部、静态、高度刻板的

1.2 核心洞察：计算 vs 检索

标准 Transformer 缺乏原生的知识查找原语，迫使当前 LLMs 通过计算模拟检索。例如，解决一个常见的多 token 实体需要消耗多个早期层的注意力和前馈网络。这个过程本质上是对静态查找表的昂贵运行时重建，浪费了宝贵的序列深度，而这些深度本可以分配给更高级的推理。

1.3 Engram 的解决方案

Engram 通过引入条件记忆作为 MoE 条件计算的补充稀疏性维度来解决这一问题：

关键特性：

  • O1 查找: 通过现代化的 N-gram 嵌入实现
  • 分层哈希: 利用 N-gram 的 Zipf 分布特性
  • 上下文感知门控: 动态调节检索的静态记忆与主干的集成
  • 确定性寻址: 支持运行时预取，可扩展到大规模参数

Engram 通过将局部依赖委托给查找操作，释放注意力容量用于全局上下文。这解释了为什么 Multi-Query NIAH 的准确率从 84.2% 提升到 97.0%——注意力机制不再被消耗在局部模式匹配上，而是能够专注于全局上下文中的关键信息检索。

4. 系统效率与可扩展性

分析问题
  • Engram 的推理开销有多大？

4.1 推理吞吐量测试

Engram 相比基于路由的 MoE 架构具有关键的系统优势：其稀疏激活通过显式、静态的哈希 ID 寻址。这产生了严格确定性的内存访问模式：一旦 token 序列已知，下一个 Engram 查找的索引就固定了，可以在相应层执行之前计算。

测试设置：

  • 硬件: NVIDIA H800
  • 工作负载: 512 序列
  • 序列长度: Uniform100, 1024
  • 配置: 将 100B 参数的 Engram 层完全卸载到主机 DRAM

结果：

  • 4B Dense 基线: 9,031.62 tok/s
  • 4B Dense + 100B Engram CPU offload: 8,858.28 tok/s 仅 -1.9%
  • 8B Dense 基线: 6,315.52 tok/s
  • 8B Dense + 100B Engram CPU offload: 6,140.02 tok/s 仅 -2.8%

4.2 关键机制：通信-计算重叠

早期密集块的计算强度提供了充足的时间窗口来掩盖检索延迟。至关重要的是，每步的有效通信量与激活的插槽数量而非总嵌入表大小成比例。

这个实验是一个保守的基线。虽然分层设计利用 Zipf 局部性将频繁项目缓存在 HBM 中，但实验设置强制所有检索都从主机内存通过 PCIe 总线传输。即使在这种最坏情况下，吞吐量损失仍然不到 3%，这表明完全优化的、感知局部性的实现会产生可忽略的吞吐量损失。

4.3 可扩展性优势

Engram 的确定性寻址带来了额外的系统优势：

1. 运行时预取: 索引可以在计算开始前计算

2. 内存层次利用: 高频 N-gram 可以缓存在 HBM

3. 通信优化: 有效通信量与激活量成正比，而非总表大小

4. 负载均衡: 哈希分布天然均衡，无需复杂调度

5. 机制分析与洞察

分析问题
  • Engram 如何改变模型的表示学习？
  • 为什么移除 Engram 后知识检索任务会崩溃？

5.1 有效的网络深度

核心发现：Engram 功能上等同于增加模型的深度。

通过 LogitLens 和 CKA（中心核对齐）分析，研究者发现 Engram 加速了预测收敛并提高了表示对齐。机制分析揭示，Engram 释放了主干网络的早期层，使网络对复杂推理"有效加深"。

实体解析示例：

  • 层 1-2: "United Kingdom 中的国家" → "Wales"
  • 层 3: "欧洲的国家" → "Wales"
  • 层 4: "女王在位期间持有的头衔" → "威尔士王妃（未指定）"
  • 层 5: "威尔士亲王妻子获得的头衔" → "威尔士王妃（未指定）"
  • 层 6: "戴安娜，威尔士王妃（1961-1997）" → "戴安娜，威尔士王妃"

在没有 Engram 的情况下，这些早期层需要消耗大量计算来静态重建实体，而在有 Engram 的情况下，这些知识可以直接检索，释放的容量用于更深层的推理。

6. 稀疏分配问题与 U 型缩放定律

分析问题
  • 什么是稀疏分配问题？
  • U 型缩放定律如何指导模型设计？

6.1 稀疏分配问题

研究者形式化了稀疏分配问题：在神经网络计算（MoE）和静态记忆（Engram）之间找到最优权衡。这个问题涉及在以下维度上分配稀缺的计算和内存资源：

1. 专家数量（MoE 容量）

2. Engram 参数量（记忆容量）

3. 激活策略（每层激活多少）

4. 插入位置（在哪层注入记忆）

6.2 U 型缩放定律

通过系统实验，研究者发现了U 型缩放定律：

  • 过多神经计算：模型浪费在重新发现已知模式上
  • 过多静态记忆：模型缺乏灵活性，泛化能力下降
  • 最优平衡点：在特定比例下达到峰值性能

这个定律指导了 Engram 的缩放策略：

  • Engram-27B: 5.7B Engram 参数（21% 总参数）
  • Engram-40B: 18.5B Engram 参数（47% 总参数）

实验表明，Engram 参数占总参数的 20-50% 是一个合理的范围，具体取决于任务需求。

7. 与现有方法的对比

分析问题
  • Engram 与其他 N-gram 嵌入方法有何不同？
  • 为什么 Engram 能在严格的等参数对比中胜出？

7.1 相关工作对比

N-gram 建模与嵌入缩放：

  • 经典方法: FastText、平滑技术（Katz, 1987; Kneser and Ney, 1995）
  • 现代嵌入缩放: Per-Layer Embeddings、DeepEmbed（扩展通过大规模表）

组合 N-gram 结构（最相关）：

  • SuperBPE: 通过将多词表达式合并为"超级词"token 来针对高频模式
  • SCONE: 通过辅助编码模型针对高频模式
  • OverEncoding: 在 token 级别捕获局部依赖的哈希 N-gram 嵌入
  • Byte Latent Transformer BLT: 在字节级别捕获局部依赖的哈希 N-gram 嵌入

7.2 Engram 的独特优势

Engram 与现有方法的关键区别：

1. 建模和评估协议：

现有方法通常将 N-gram 嵌入视为外部增强，未在严格公平的比较协议下验证效率

Engram 将条件记忆作为第一类建模原语，在稀疏分配框架内严格评估

2. 系统视角：

现有方法将嵌入严格放在输入层（Layer 0），序列化内存访问和计算

Engram 战略性地将内存注入更深层，以启用通信-计算重叠

利用 N-gram 的固有的 Zipf 分布，最大化硬件内存层次的效用

3. 架构集成：

现有方法通常是"附加"模块，需要额外的训练 FLOPs

Engram 与主干深度集成，门控机制实现动态控制

8. 局限性与未来方向

分析问题
  • Engram 的主要局限性是什么？
  • 未来研究可以如何改进条件记忆架构？

8.1 当前局限性

1. 静态记忆的固化: Engram 存储的是静态 N-gram 模式，难以快速更新知识

2. 哈希冲突: 分层哈希可能引入噪声，需要精心设计

3. 门控学习: 上下文感知门控需要大量训练数据才能学到有效策略

4. 内存占用: 大型 Engram 表需要显著的内存存储

8.2 未来研究方向

1. 动态记忆更新: 设计机制允许在训练后更新 Engram 表而不重新训练整个模型

2. 自适应哈希: 学习式哈希函数减少冲突并提高查询质量

3. 分层记忆设计: 多级记忆层次，结合快速静态查找和慢速动态检索

4. 跨模态扩展: 将条件记忆扩展到视觉、音频等多模态场景

5. 硬件协同设计: 与硬件厂商合作优化 Engram 的硬件加速

8.3 应用前景

Engram 的条件记忆架构有广泛的应用前景：

1. 边缘设备: 确定性寻址和预取适合边缘部署

2. 实时系统: O1 查找支持低延迟应用

3. 知识密集型任务: 专门优化的知识检索能力

4. 长上下文应用: 注意力容量解放支持长文档、长对话

9. 结论

分析问题
  • Engram 对未来 LLM 架构设计意味着什么？
  • 条件记忆是否会成为下一代模型的标配？

9.1 关键贡献

Engram 论文的核心贡献可以总结为：

1. 新稀疏性维度: 引入条件记忆作为 MoE 条件计算的补充

2. O1 查找: 通过现代化 N-gram 嵌入实现高效知识检索

3. 性能提升: 在严格的等参数、等 FLOPs 条件下显著优于 MoE 基线

4. 机制洞察: 揭示 Engram 如何有效加深网络、解放注意力容量

5. 系统效率: 100B 参数模块实现 3% 的吞吐量损失

9.2 设计启示

Engram 为未来的 LLM 架构设计提供了重要启示：

1. 双重稀疏性: 神经计算和静态记忆的协同设计

2. 原语优先: 将条件记忆作为第一类建模原语

3. 算法-系统协同: 利用硬件特性的算法设计

4. 任务感知: 根据任务性质分配计算资源

9.3 未来展望

研究者展望条件记忆将成为下一代稀疏模型不可或缺的建模原语。随着模型规模的持续增长和任务复杂度的提升，条件记忆的潜力将进一步显现：

  • 可扩展性: 可扩展到更大规模的模型和更长上下文
  • 泛化能力: 跨语言、跨任务的泛化表现优异
  • 实用性: 严格的系统效率分析支持实际部署

正如论文标题所述，Engram 实现了"通过可扩展查找的条件记忆"，为大语言模型的稀疏性探索开辟了新的道路。
